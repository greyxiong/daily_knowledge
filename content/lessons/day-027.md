# 每日认知模型 #27：委托—代理问题（Principal–Agent Problem）

昨天的 **古德哈特定律**告诉我们：**指标一旦成为目标，人就会开始优化指标，而不一定优化真实目标。**

今天再往下挖一层：**为什么组织里这种事情几乎必然发生？**

答案是一个横跨经济学、公司治理、金融、政治学和产品管理的重要模型——**委托—代理问题**。

## 1｜它是什么

当 **A 想让 B 替自己做事，但 A 和 B 的利益并不完全一致，而且 A 无法完全观察 B 的行为**，就产生了委托—代理问题。

最简单的结构是：

**Principal（委托人） → 授权 → Agent（代理人）**

但 Agent 通常同时拥有两样东西：

**自己的利益 + 比 Principal 更多的信息。**

于是就可能出现：

> Agent 做了“对自己最优”的事，却不一定是“对 Principal 最优”的事。

关键并不是“Agent 人品不好”。

即使所有人都很理性、很职业，这个问题仍然会存在，因为它来自**结构本身**。

---

## 2｜直觉：想象你雇了一个基金经理

你的目标是：

> **长期、风险调整后的财富增长。**

基金经理的目标可能是：

> **今年业绩排名不要太差 + AUM 不要下降 + 奖金最大化。**

于是出现一个微妙的问题。

假设基金经理认为某家公司长期很好，但未来一年可能跑输市场。

从你的角度：

> 应该持有。

从基金经理角度：

如果别人都买 AI 股，他不买：

AI 涨 → 他排名落后 → 客户赎回 → 奖金下降。

于是他的理性选择可能是：

> **跟大家一起买。**

即使他本人并不认为这是长期最优配置。

这就是委托—代理问题。

你不能简单地说：

> “基金经理应该以客户利益为先。”

因为真正应该问的是：

> **这个系统给他的激励是什么？**

这正好接回我们 Day 12 学过的**激励模型**。

---

## 3｜一个真实世界的经典场景：上市公司管理层

股东理论上希望：

> **公司长期内在价值最大化。**

CEO 却可能同时在乎：

薪酬、任期、股价短期表现、个人声望、公司规模。

于是一个非常重要的投资问题出现：

> **CEO 为什么要收购另一家公司？**

表面理由可能是：

“协同效应。”

但投资者应该继续问：

如果不收购：

CEO 管理一家 $20B 的公司。

如果收购：

CEO 管理一家 $50B 的公司。

更大的公司往往意味着更大的组织、更高的影响力，甚至更高的薪酬。

于是：

**扩大公司规模 ≠ 提高每股内在价值。**

这也是为什么研究公司不能只研究：

> TAM、产品、竞争。

还必须研究：

> **Management incentives / Capital allocation。**

# 4｜应用到产品工作

假设公司真正目标是：

> **提高长期用户价值。**

但组织结构变成：

产品经理 KPI = DAU  
增长团队 KPI = 新增用户  
商业化团队 KPI = Revenue  
风控团队 KPI = Loss Rate

于是每个人都可能**完美完成 KPI，但公司整体变差**。

例如风控：

Loss Rate 太高。

于是风控把规则收紧。

结果：

欺诈 ↓

但同时：

正常用户被拒绝 ↑  
支付成功率 ↓  
GMV ↓

风控团队：

> KPI 完成。

公司：

> 生意变差。

这里非常重要的一点是：

**不要怪风控。**

如果你是那个负责人，而且绩效完全按照 Loss Rate 评价，那么收紧规则可能就是理性行为。

真正的问题是：

> **Principal 给 Agent 设计了错误的目标函数。**

# 5｜现在把 Day 12、26、27 串起来

这三个模型实际上是一套完整的组织诊断工具：

**Day 12 激励**

告诉你：

> 人会响应激励。

↓

**Day 26 古德哈特定律**

告诉你：

> 一旦把 proxy 变成 KPI，人就会优化 proxy。

↓

**Day 27 委托—代理问题**

进一步告诉你：

> 为什么 Agent 会优化 KPI，而不是你脑子里的“真正目标”。

因为真正目标：

**通常不可观察、不可量化，也无法直接写进绩效。**

所以管理的核心难题之一，其实是：

> **如何让局部理性 ≈ 全局理性。**

---

# 6｜以后看到组织问题，自动问这四个问题

不要先问：

> 谁做错了？

先问：

**① Principal 是谁？**

真正承担结果的人是谁？

**② Agent 是谁？**

谁替他做决定？

**③ 两者目标哪里不一致？**

不要假设“大家目标一致”。

把它明确写出来。

**④ Agent 掌握什么 Principal 看不到的信息？**

这叫 **information asymmetry（信息不对称）**。

这一步尤其重要。

因为：

> **利益不一致 + 信息不对称**

往往就是代理问题最危险的组合。

# 7｜小练习

选一个你熟悉的公司场景。

比如：

> 公司希望提高产品长期用户价值。

然后填：

| 问题 | 你的答案 |
|---|---|
| Principal | 公司 / 股东 |
| Agent | 产品团队 |
| Principal 真正想要 | 长期用户价值 |
| Agent 被考核什么 | 例如 DAU |
| Agent 知道、Principal 不知道什么 | 具体产品操作如何影响 DAU |
| Agent 最容易 gaming 什么 | Push、红点、激励等 |
| 最终可能发生什么 | DAU ↑，长期留存 ↓ |

然后做最后一步，也是最重要的一步：

> **如果不能取消 KPI，你会怎么重新设计激励，让 Agent 的最优策略更接近公司的最优策略？**

这一步会迫使你从“发现组织问题”，进入真正的**机制设计（Mechanism Design）**。

今天只需要记住一句：

> **判断一个系统，不要听参与者说自己想做什么；先看他们因为什么得到奖励。**

下一层自然会进入一个更深的问题：**即使我们知道激励错配，怎样设计规则，让每个人追求自身利益时，系统仍然产生我们想要的结果？** 这就是博弈论与机制设计开始介入的地方。
