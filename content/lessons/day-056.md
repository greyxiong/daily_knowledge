# 每日认知模型 #56：信号检测理论（Signal Detection Theory）

昨天的 **Bayesian Updating** 解决的是：获得新证据后，我应该把判断更新多少？

今天再向前一步：现实中我们通常不能无限收集证据，最终必须做一个二元动作——**拦还是不拦、批还是不批、报警还是不报警、上线还是不上线。**

于是问题变成：

> **证据达到什么程度，我才应该行动？**

这就是 **Signal Detection Theory（信号检测理论，SDT）**。它最早发展于雷达与心理物理学，但现在广泛适用于医学检测、风控、机器学习、内容审核和产品决策。

## 1｜它是什么

假设你负责支付风控，每笔交易背后存在两个真实状态：

\[
Fraud \quad / \quad Legitimate
\]

但你看不到真实状态，只能看到一个风险分数。

欺诈交易通常分数更高，但两个分布会重叠：

```text
低风险                         高风险
        正常交易
      ███████████
    ███████████████
             ██████████
                 欺诈交易
               ███████████
```

于是你必须画一条线：

\[
Risk\ Score > T \Rightarrow Block
\]

这个 \(T\) 就是 **Decision Threshold（决策阈值）**。

任何阈值都会产生四种结果：

| 真实情况 | 允许 | 拦截 |
|---|---|---|
| 正常交易 | True Negative | **False Positive** |
| 欺诈交易 | **False Negative** | True Positive |

核心问题因此不是：

> “怎样做到完全准确？”

因为只要两个分布存在重叠，完美分类通常就不存在。

真正的问题是：

> **我愿意交换多少 False Positive 来减少 False Negative？**

---

## 2｜直觉：为什么机场安检和垃圾邮件不能用同一个阈值？

假设一个检测系统都能做到：

**漏掉危险对象概率 1%**

**误报正常对象概率 10%**

用于机场安检时，你可能愿意接受大量误报：

> 多检查一些正常行李，总比漏掉真正危险对象好。

但用于垃圾邮件：

如果为了少漏一封垃圾邮件，把 10% 正常邮件扔进垃圾箱，这个系统几乎不可用。

算法准确率可能完全相同。

但最优 threshold 完全不同。

因为：

\[
Cost(FP)\neq Cost(FN)
\]

所以**分类问题首先是经济决策问题，其次才是模型准确率问题。**

---

## 3｜真实例子：烟雾报警器为什么故意“有点烦”

烟雾报警器偶尔会因为做饭产生误报。

从纯准确率角度看，这似乎是产品缺陷。

但考虑损失函数：

\[
Cost(False\ Alarm)=几分钟麻烦
\]

而：

\[
Cost(Missed\ Fire)=可能极其严重
\]

于是合理设计自然会把 threshold 调低：

> **宁愿多报几次，也不要轻易漏掉真正火灾。**

这不是系统“不准确”。

而是系统针对**非对称损失函数（Asymmetric Loss Function）**进行了优化。

这也是为什么看到一个系统“误报很多”时，不能直接判断它差。

先问：

> **漏报的代价是多少？**

---

## 4｜应用到产品：KYC / Fraud 最典型

假设一个风控模型 threshold 调高以后：

Fraud loss：

\[
\$10M\rightarrow \$6M
\]

看起来非常成功。

但与此同时：

正常用户被拒：

\[
2\%\rightarrow8\%
\]

导致支付 TPV 损失 $12M。

如果团队 KPI 只有：

> Fraud Rate

模型团队会非常开心。

但整个业务可能变差。

真正目标应该类似：

\[
Expected\ Loss(T)
=
FP(T)\times C_{FP}
+
FN(T)\times C_{FN}
\]

然后寻找：

\[
T^*=\arg\min Expected\ Loss(T)
\]

注意这里发生了一个重要变化：

我们不再寻找：

> **“最准确的模型”。**

而是在寻找：

> **“商业损失最小的决策规则”。**

这和 #50 **Goodhart's Law** 直接连接：如果只把 fraud rate 作为目标，系统自然会通过大量误杀正常交易来优化 KPI。

## 5｜它对普通 PM 决策也非常有用

假设你判断一个新产品 idea：

> **值得做 / 不值得做。**

你其实也在做 Signal Detection。

世界真实状态：

**Big Opportunity / Bad Opportunity**

你的判断：

**Build / Don't Build**

于是同样存在四格：

| | Bad Opportunity | Big Opportunity |
|---|---|---|
| Don't Build | 正确放弃 | **错过机会** |
| Build | **浪费资源** | 抓住机会 |

现在真正重要的问题出现了：

> **你所在业务的 False Positive 和 False Negative，哪个更贵？**

成熟业务资源紧张：

错误 Build 一个项目可能浪费几十人半年。

所以 threshold 应该高。

早期创业公司：

真正危险的可能不是做错三个实验，而是错过唯一一个巨大机会。

所以 threshold 可以更低。

这解释了为什么：

> **同一个 idea，在不同公司里可能应该得到完全不同的决策。**

不是谁分析错了，而是双方的 **loss function 不同**。

## 6｜和昨天的 Bayesian Updating 合起来

昨天我们可能得到：

\[
P(\text{这个AI产品会成功}\mid Evidence)=65\%
\]

很多人会继续问：

> “65% 到底算会还是不会？”

这是错误问题。

Bayesian inference 到这里已经完成了。

接下来应该交给 Decision Theory：

如果做：

成功收益 = +100  
失败损失 = −20

那么即使成功概率只有：

\[
25\%
\]

可能都值得下注。

反过来，如果：

成功收益 = +20  
失败损失 = −100

即使成功概率：

\[
65\%
\]

也未必值得做。

因此：

\[
Probability \neq Decision
\]

更完整的框架是：

\[
Evidence
\rightarrow
Posterior Probability
\rightarrow
Payoff/Loss
\rightarrow
Decision Threshold
\rightarrow
Action
\]

**贝叶斯告诉你世界有多可能是什么样。**

**Signal Detection / Decision Theory 告诉你面对这个概率应该做什么。**

## 7｜把 #52–56 串起来

现在我们已经形成了一条非常接近实际产品决策的完整链条：

**#52 Counterfactual**  
→ 如果没有 X，本来会发生什么？

**#53 Simpson's Paradox**  
→ 总体数据是不是被 population mix 扭曲？

**#54 DAG**  
→ 哪些变量是 Confounder / Mediator / Collider？

**#55 Bayesian Updating**  
→ 新证据应该让我更新多少概率？

**#56 Signal Detection Theory**  
→ **概率更新以后，达到什么 threshold 我才行动？**

所以以后不要只问：

> “这个项目成功概率是多少？”

再补两个问题：

> **做错的成本是多少？**

> **不做但其实应该做的成本是多少？**

很多困难决策真正的分歧，并不是大家对 probability 判断不同，而是大家隐含使用了完全不同的 **error cost**。

## 今日小练习：给自己的产品决策画一个 2×2

选一个真实的产品 idea。

只写四格：

| | Idea 实际很差 | Idea 实际很好 |
|---|---|---|
| **不做** | 正确放弃 | 错过机会 |
| **做** | 浪费资源 | 抓住机会 |

然后分别给四个格子一个粗略价值，例如：

\[
0,\quad -100,\quad -20,\quad +200
\]

接着问：

> **成功概率至少达到多少，我才应该做？**

如果失败损失是 −20，成功收益是 +200，那么 break-even probability 约为：

\[
p(200)+(1-p)(-20)>0
\]

得到：

\[
p>9.1\%
\]

这意味着一个**只有 15% 成功概率**的项目，也完全可能是理性选择。

今天留下的条件反射是：

> **不要问“我有多确定以后才行动？”；问——“在做错和错过的代价不同的情况下，我究竟需要多大概率才值得行动？”**

这一步把我们从 **预测世界** 推进到了真正的 **决策科学**。
